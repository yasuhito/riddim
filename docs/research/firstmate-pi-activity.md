# Firstmate の Pi 活動判定 (ソース調査)

調査対象は `/home/yasuhito/Work/oss/firstmate` の作業チェックアウト、HEAD `ac2ed3b2`。調査時 `git status --short` は空で、`main` は `origin/main` より3コミット遅れている。以下の `bin/...`、`.pi/...`、`tests/...` はすべてこの Firstmate チェックアウト相対の参照。ソースとテストを静的に読んだ結果であり、稼働中の Pi/Herdr を観測・操作した結果でも、過去の Riddim の Pi 問題の原因診断でもない。テストは実行していない。

## 判定するもの、判定しないもの

- **Thinking / stream 無音 / 画面無変化は wedge の証拠ではない。** Pi のタスク別 extension は `agent_start` を `busy` と記録し、`agent_settled` で `ctx.isIdle()` が明示的に false の場合は busy を維持し、それ以外は `idle` と記録する。内側の `turn_end` は通知用ファイルを touch するだけ。自動再試行・tool loop・継続中は settled としない。`codex-native:progress` だけは別の進捗 marker を更新する (`bin/fm-spawn.sh:4291-4332`)。`busy` 判定は世代一致・信頼済みソースのレコードを優先し、欠損/不正/古いレコードを安易に `idle` にしない。レコードがない Herdr の native `working` は `busy` にできるが native `idle` は Pi のターン完了の証拠にならない (`bin/fm-busy-lib.sh:4-10,52-74,1011-1068,1083-1092`)。Herdr の `working` は busy、`idle|done|blocked` は idle とする backend の生の写像とは用途が違う (`bin/backends/herdr.sh:3523-3536,3564-3583`)。Calm の working 表示も `agent_start` から `agent_settled` まで維持する (`.pi/extensions/fm-calm.ts:128-149,461-475`)。**約13分の「Thinking...」の後に再開した事例は、それだけでは停止の証拠ではない。** 文字出力の途絶時間、CPU、プロセス sleep 状態や単なる marker mtime は semantic state の根拠にしない (`bin/fm-busy-lib.sh:4-12`)。
- **無出力だが busy:** watcher は通常15秒周期、Pi の正確な `busy` は画面 hash が同一でも基本的に吸収する。完了ターン (`*.turn-ended`)、その前は spawn 時の `*.meta`、より新しい明示的 native progress を起点として、`FM_BUSY_TURN_MAX_SECS` 既定3600秒を超えて初めて共通 wedge *疑い* timer に入る。そこから `FM_STALE_ESCALATE_SECS` 既定240秒の無進展で `possible wedge` を通知する。表示フッターが刻々変化しても同じ規則 (`bin/fm-watch.sh:229-240,273-290,1362-1380,2740-2765,2888-2913`)。進捗 marker は Pi では `codex-native:progress` のみに紐付け、一般的な無音の全てを計測する仕組みではない (`bin/fm-spawn.sh:4314-4332`)。テストは Pi busy の5分と66分を境界として既定3600秒を確認し、別テストは完了ターンなしの native progress で timer が消えることを確認する (`tests/fm-watch-triage.test.sh:4890-4933,4500-4534`; `tests/fm-busy-state.test.sh:577-590`)。
- **busy と証明できず、画面 hash が連続して同じ:** 2回の同一 hash で stale 候補になる。ただし「無出力」だけから即座に wedge と確定しない。稼働中の検証 step 等で作業中と証明できれば吸収して240秒 timer、宣言済み待機なら長周期再確認、それ以外の非終端状態なら直ちに supervisor へ `stale` を通知して確認を促す。terminal な古い status も稼働中の step があれば上書きして誤報を避ける (`bin/fm-watch.sh:2719-2722,2750-2767,2791-2837,2843-2886`)。hash 変化もそれ単独では実作業の進展ではない (`bin/fm-watch.sh:2888-2938`)。
- **idle / turn-end:** Pi の `agent_settled` による idle は logical run の終了、`turn_end` はその内側の境界通知であって必ずしも idle ではない (`bin/fm-spawn.sh:4293-4317`)。主セッションの Pi watch extension は watcher の actionable wake を `sendUserMessage(..., { deliverAs: "followUp" })` で届ける。stream 中の follow-up は `before_agent_start` を経ないことがあるため、受信確認は該当 `message_start` でも行う (`.pi/extensions/fm-primary-pi-watch.ts:16-25,570-596`)。これは監督通知と watcher の継続であり、無音の Pi ターンを中断・再実行する処理ではない。再 arm の最大5回の retry は **watcher 自体** の継続失敗用 (`.pi/extensions/fm-primary-pi-watch.ts:155,945-983`)。
- **死んだプロセスと生きていて固まった疑いは別:** process identity の表に `pi|pi-signed|pi-launcher|Pi` があり、名前/argv 等を分類する (`bin/fm-agent-process-lib.sh:21-25,39-51,77-113`)。Herdr は pane/agent の構造化応答に process view を重ねる。shell-only のまま残る `working` 登録は live としないが、読めない場合は unknown にして破壊的な判断を拒む (`bin/backends/herdr.sh:2213-2286,2328-2362,3564-3583`)。wedge timer の直前に backend を検査し `dead|missing` の確証があれば「not a wedge」と一度だけ知らせ、同一 incarnation の反復 alarm を抑制。`alive|ambiguous|unreadable|unverified` は引き続き疑いとして通知する (`bin/fm-watch.sh:1243-1307`)。

## 通知と誤検知対策

- 240秒 timer は確定診断ではなく `possible wedge, escalation N`。同一 pane で既定3回連続なら `demand-deep-inspection` を付ける。**人が詳しく調べるための通知のみで、worker/tool を自動 interrupt、signal、restart しない** (`bin/fm-watch.sh:62-77,273-290,1329-1362`; `tests/fm-watch-triage.test.sh:4342-4353,4550-4584`)。事前に本人が宣言した `paused:` / 確認済み captain-held、任意設定 `config/wedge-defer-parked-gate` 下の未解決の人間判断待ち、静かな間に task worktree へ実際の書き込みがあった場合は疑いを延期する。延期は取消しではなく timer を再開し、既定14400秒の長周期で待機を再確認する。期限切れの `paused: ... until` は待機の証拠にしない (`bin/fm-watch.sh:985-1009,1037-1135,1138-1232,1329-1356,1388-1440`; `bin/fm-classify-lib.sh:109`)。テストは宣言待機を wedge と誤表示しないこと、未設定 gate では元の escalation を維持することを確認する (`tests/fm-watch-triage.test.sh:2820-2888,3160-3187`)。
- **別の wedge alarm と混同しない:** `config/wedge-alarm` は Pi worker の思考無音アラームでなく、away-mode daemon が supervisor 宛の buffered escalation を投入できない場合のアラーム。既定 `FM_MAX_DEFER_SECS=300` を超えたら通常配送を再試行、なお配送確認できなければ durable marker と buffer/queue を残し、最大 defer 間隔で rate-limit した通知を送る (`bin/fm-supervise-daemon.sh:207-217,948-995,1035-1059`)。macOS 既定は osascript、その他 OS は既定の OS channel なし。`config/wedge-alarm` で `off|auto|osascript|herdr|command:` を選べ、notifier は既定10秒に制限する (`bin/fm-supervise-daemon.sh:718-779,957-992`; `tests/fm-daemon.test.sh:2472-2505`)。`fm-timeout-lib.sh` の期限は呼び出された **コマンド** を境界内に収めるためのもの、Pi の思考全体の無音検出ではない (`bin/fm-timeout-lib.sh:2-38`)。
- **監督の欠落も別問題:** Pi 主セッションは watcher extension と turn-end guard の版・session PID が一致し生存する場合だけ、一時的な watcher lock の空きを正常な hand-off と認める。beacon が古ければ異常になり、guard は settled 時に監督の修復を促す follow-up を送る。監督回復と worker の推論再起動を同一視しない (`bin/fm-wake-lib.sh:186-216,268-276,375-429`; `.pi/extensions/fm-primary-turnend-guard.ts:603-625`)。

限界: 判定は記録された endpoint、hook、status、作業状態、読み取り成功に依存する。`busy` が続く13分は既定の busy-turn 閾値未満であり、それだけで Firstmate が「本物の wedge」と扱う根拠はない。一方、記録欠落や明確な idle、無証明の stale は早く通知され得るが、いずれも人の調査を求めるものであり、過去の Riddim 事象の原因を示さない。
